P1

接入与守卫Intake & Guard

出处：docs/dynamic-dataset-workflow.md 步骤 1–3 · input/README.md
P1.1
人工

新源图 PNG 放入 input/pending/

未处理的收入/损益表信息图截图；input/processed/ 存放已定稿的稳定参考图。

P1.2
自动

运行 pending 守卫

pnpm check:pending
  • 对每张 pending PNG 计算 sha256，与 input/processed/ 全部图片做精确内容比对；
  • 从文件名推导候选 dataset key（去掉 page-N 前缀、income-statement 后缀，转小写 kebab）；
  • 检查候选 key 是否已有四类 artifact：processed 图片、data/datasets/<key>.js、index.html 注册、损益表 SSOT 记录。
实现：scripts/check-pending-processed.mjs
D1 · 内容与已处理图完全一致（already-processed），
或候选 key 与现有 artifact 冲突（key-collision）？
是 — 停止条件
STOP

报告停止条件，流程终止

对该图片不得移动、创建、更新、裁剪或验证任何内容；只在最终回复中报告冲突详情。

否 — 继续
P1.3
人工

确定最终稳定 key

小写 kebab：<company>-<period>，如 nvidia-q4-fy26。

若最终 key ≠ 脚本候选 key：须再到 input/processed/、data/datasets/、data/income-statements/、index.html 四处复查最终 key 无冲突。

P1.4
人工

移动图片到 input/processed/<dataset-key>.png

记录精确宽高（供 meta.referenceImage）。命名后永不改名；公司或期间变化时创建新 key、新文件。

创建公司档案 SSOT

data/company-metadata/<company-key>.js：description、sector、industry、founded、headquarters、fiscalYearEnd、website、ticker/exchange、marketCap（含 asOf/source）、sourceUrls，加每种非默认语言的本地化 profile，并注册进 index.html。

P2.2
人工

写入损益表 SSOT 记录

data/income-statements/<company-key>.js（新公司则建文件并注册 index.html）：可比报告总额、line items、notes、currency、unit、period、sourceImage。

  • 纯数据边界：不得包含 Sankey nodes / links / layout / render / SVG / 颜色 / 像素几何；
  • 货币契约：currency 必须经 src/trace-domain.js 别名解析到 USD_FX_SNAPSHOT 汇率；新报告货币要在同一次变更中扩展快照（注明日期与来源）；
  • 发布方 rounding 差异用 roundingTolerance 吸收。
D3 · 源图含公司 / 业务线 / segment 图标？水印、attribution、无独立图标的 “Others” 类 segment 不算
是 — 进入图标子循环
图标 Crop / Vector 子循环（可先于整图循环）
P2.3a
人工

编写 crop spec

input/icon-crop-specs/<dataset-key>.json：只含坐标、过滤、输出名与备注。要求覆盖每个有语义的公司 / 业务簇（跳过水印、署名、无图标 segment）。

P2.3b

python3 scripts/extract_icon_crops.py \ --spec input/icon-crop-specs/<dataset-key>.json

输出到 data/assets/icon-references/<company>/：透明背景 crops/、validation-sheets/、crop-report.json。

P2.3c
人工

逐张验收 validation sheet

  • 主体完整、视觉居中、无无关文字 / 连线 / 水印 / 相邻图标；
  • 看 crop-report.json 的 transparentPixelRatio：接近 0 说明背景没抠掉 → 在 spec 里显式钉住 backgroundRemoval.color 重跑。
D3a · crop 合格？
不合格 → 改 spec 重新 crop（回 P2.3a），不得基于错误 crop 继续
P2.3d
人工

记录验收 + 资产落点

  • 验收结论写入 model-validation.md；
  • 优先复用 / 矢量化：materially similar 的已有 vector 直接复用；通用语义用 src/icons.js Lucide；可复用 vector 存 SANKEY_BUSINESS_ICONS；一次性 logo 放 dataset 的 meta.logoSvg；vector 候选与 crop 同尺寸算 Diff 收敛；
  • raster 白名单例外：仅当已验证 cluster 经 spec 的 runtimeOutputDir 生成 data/assets/raster-annotations/<company>/ 副本，且 dataset 显式 render.allowRasterAnnotations = true；
  • icon-references/ 下的 crop 是纯参考资产，永不被 d3 运行时直接引用。
否
—

无图标提取，跳过子循环

P3

Adapter 与 i18nSankey 视图适配层

出处：docs/dynamic-dataset-workflow.md 步骤 6、8–9 · data/schema.md · docs/fidelity-loop-rules.md §第 0 轮
P3.1
人工

第 0 轮：渲染前测量（写 adapter 之前）

直接从参考图测量，不允许先粗排、再靠保真轮次逼近：

  • 画布尺寸、各列节点 x 位置；
  • 每个短辅助柱 / 短横柱 / 终端柱的像素 bbox（x/y/width/height）；
  • 逐条追踪 link 拓扑：source、target、socket，特别是 waterfall 区、绕行带、多入口目标柱；
  • 每个 label 的锚点、anchor 方向、语义归组（名称/数值/备注/margin/Y-Y 同组）；
  • 注释容器、KPI/stat card、徽章的容器 bbox。
历史教训：跨 10+ 轮才收敛的数据集，其后期修复项几乎全部可以在首轮测量时一次做对。
P3.2
人工

编写高保真 adapter：data/datasets/<dataset-key>.js

  • 显式 nodes + links + layout.nodes + layout.labels（低级格式，见 data/schema.md）；
  • meta.referenceImage 指向 processed 图并写精确宽高；成本为正数（type:'cost' 渲染为括号）；
  • 语义 label 单元先归组、再拆 blocks / lines；保留源图数值与 notes；
  • 发布方水印、创作者品牌、URL、attribution 是有意跳过残留，不是渲染目标；
  • 源图有可矢量化 logo 时设 meta.logoSvg。
P3.3
人工

i18n overlay（英文为规范源）

  • 对每种非默认语言（当前 zh）加 i18n.<language> overlay——绝不建平行数据集文件；
  • 覆盖 dataset name / meta / node labels+notes / 每条会变化的固定 layout.labels 与 annotation 行，以及 SSOT labels/notes、公司档案；
  • overlay 仅限显示层：不得改 values、links、node 几何、财务总额、源图、验证语义；
  • 有意不翻译的子品牌词（如 aws）→ dataset 的 i18n.preservedAnnotationText；全局不翻译品牌词（YouTube、iPhone…）→ src/i18n.js 的 EXACT_ZH 恒等映射。
P3.4
混合

注册进 index.html

在依赖脚本与被复用数据集之后追加 <script> 标签。磁盘 ↔ 注册奇偶由 verify:ssot 强制，漂移可用：

pnpm sync:index-datasets
P4

验证聚合门 + 人工保真循环

出处：docs/fidelity-loop-rules.md（循环 SSOT）· scripts/verify-dataset.mjs
P4.1
自动

单数据集聚合门

pnpm verify:dataset -- <dataset-key>

按序执行，任一步失败即终止：

  • ① node --check：dataset 与支持数据文件语法；
  • ② verify:ssot：SSOT ↔ dataset 数值奇偶、注册奇偶、货币/单位 + FX 覆盖；
  • ③ verify:i18n --strict <key>：overlay 覆盖率（不证明视觉有效）；
  • ④ verify:dataset-file-metadata：生成的 metadata 是否新鲜；
  • ⑤ verify:d3 <key>：默认语言渲染 + 自动硬门槛；
  • ⑥ verify:d3 <key> --language zh：每种非默认语言各渲染一次。
人工 d3 保真循环 — 效率目标：3 轮内清空人眼显著错误，4–5 轮完全收敛
P4.2
自动

每轮渲染 + 自动哨兵 + 归档

pnpm verify:d3 -- <dataset-key> --focus "<本轮主检查方向>" [--keep]
  • 起本地静态服务器 → 最小 harness 执行 SankeyEngine.render('#chart', data) → 截取 #chart > svg；
  • 运行自动硬门槛（11 项）：输出纯净性、SVG 尺寸 = referenceImage、Montserrat 字体、无 raster/背景图（白名单除外）、label-node 间距（bbox 间距 < 4px 即 hard fail，目标 5px）、短柱中心偏移 ≤ 4px、左右无横向 overlap、SSOT/i18n/语法一致 → 失败先修，再谈保真；
  • 计算全图 + DOM 派生分区域 Diff：mae / similarity / changedPixelRatio / diffBoundingBox / regions[]；
  • 归档：output/compare/<key>/<round>-<improvement>-<focus>/（候选图、Diff 图、metrics JSON）；compare/ 只是临时 scratch，--keep 后须 sh scripts/clean-compare.sh。
P4.3
人工

按 sweep 分层批量检查（标准预算 3 轮）

第 1 轮结构 sweep纯净性、尺寸、裁剪；节点几何、列位置、流带宽度；多入口/出口 socket 顺序；终端短横柱、自定义 curve；hub 出发 profit 流带取色核对。
第 2 轮文本 sweeplabel-node 外框三段式 bbox 审计、文本归属与位置；注释容器 / KPI card / 徽章 / 脚注内部对齐。
第 3 轮润色 + 本地化 sweep颜色、透明度、图标细节；每种非默认语言 --language zh --keep 渲染，getBBox 查混排残留、R&D / SG&A 缩写、越界、重叠。

每轮把本层能修的问题一次修完；更早层级的新问题立即修，更晚层级的记入 backlog。单方向深查轮只用于：门槛反复失败、用户重开、sweep 内修不完。

P4.4
人工

每轮闭环产物

  • 误差分类：必须死磕 / 需要优化 / 可接受残留 / 无语义跳过（无语义内容不得为压 Diff 补画）；
  • 红框参考图：以原图为底，红框圈完整语义区域，存 …/<key>-attention-reference.png；无开放问题则在 Task 信息中记「无开放红框」；
  • Task 信息：轮次、archive、主方向、已冻结、重开、backlog、红框 region 清单、下一轮方向；
  • 用户反馈沉淀：可泛化经验更新 docs/fidelity-loop-rules.md，数据集特例记入 Task 信息，然后才能声称已处理。
D4 · 收敛标准全部满足？硬门槛通过 + 死磕清单清空 + backlog 关闭 + 本地化通过 + Task/红框完整（13 条，见附录 B）
未收敛 → 下一轮 sweep 前进或升级深查；死磕清单已空且预计 similarity 提升 < 0.0005 时禁止再开新轮
P4.5

循环收敛

剩余差异记录为可接受残留 / 无语义跳过；冻结清单与最新 Task 信息完整；产出面向最终回复的 Loop Fidelity Summary（5–9 行）。

出处：docs/dynamic-dataset-workflow.md §Verification Checklist / §Reporting · docs/commit-messages.md
P5.1
人工

input/pending/ 恢复为只剩 .gitkeep

P5.2
自动

快速聚合门全绿

pnpm check

= 全仓 JS 语法扫描 → 单元测试 → check:pending → verify:ssot → verify:i18n → verify:dataset-file-metadata（秒级、无渲染）。

P5.3
人工

按约定提交

轻量 Conventional Commits：<type>(<scope>): <summary>（英文小写）。

  • 新数据集 = 一个 data(<key>) 提交：processed PNG + adapter + index.html 注册；
  • 为它新增的通用渲染能力 → 拆成前置 render(engine) 提交；
  • 正文写清运行过的验证命令与关键指标（不得把 Reference 模式结果写成 d3 验证结果）。
P5.4
人工

最终回复必含汇报项

  • 变更文件清单，纯数据 SSOT 是否更新；
  • 提取的图标资产，全部相关 cluster 已覆盖或记录为跳过；
  • 紧凑 Loop Fidelity Summary + 最新 Task 信息 + 红框图状态（或未运行循环的原因）；
  • 用户反馈经验是沉淀进规则文档、还是记为数据集特例；
  • 无法运行的命令。

附录（Review 优化时的关键上下文）

A · 自动硬门槛 11 项（每轮先过，失败先修 — docs/fidelity-loop-rules.md §自动硬门槛）
  1. 候选图必须是 SankeyEngine.render() 产生的 d3/SVG 输出；
  2. SVG 尺寸必须等于 meta.referenceImage.width/height；
  3. 本地 Montserrat 字体必须加载成功，不得用 fallback font 计分；
  4. #chart 中不得出现 <img>、canvas、foreignObject、picture、video、iframe、object、embed；
  5. 参与截图的元素不得用 CSS background-image 当像素补丁；
  6. 默认 #chart > svg image 数量必须为 0；
  7. 仅显式 runtime raster 模式允许 SVG <image>，且须满足白名单全部条件；
  8. 同轴 label 与 node 外框不得纵向交叠：目标间距 5px，渲染 bbox 间距 < 4px 即 hard fail；
  9. 短辅助柱与其上下同轴 label 水平中心 centerDelta > 4px 即 hard fail；
  10. 左右相邻 label 与 node 的横向 overlap 是 hard fail；
  11. node --check / verify:ssot / verify:i18n --strict 等数据一致性检查必须通过。
B · 保真循环收敛标准 13 条（docs/fidelity-loop-rules.md §收敛标准）
  1. 自动硬门槛通过；
  2. 候选图纯净，未使用未批准源图像素；
  3. 「必须死磕」问题域均已被 sweep 或升级深查覆盖、记录证据并冻结；
  4. 冻结清单未被相关改动或自动回归信号重开；
  5. backlog 为空，或剩余项均为可接受残留 / 无语义跳过 / 明确超范围；
  6. 本轮主方向分区域 Diff 无新的结构性高误差区域；
  7. 全图 Diff 相较上一轮已无明显可操作改善空间；
  8. 用户标注区域逐一复查并记录修复前后指标；
  9. 新增/修改过的非默认语言覆盖通过本地化布局检查；
  10. 最新 Task 信息完整（已主查 / 已冻结 / 重开 / backlog）；
  11. 每个未冻结或刚修复的用户标注区域有红框记录或关闭说明；
  12. 用户反馈通用经验已沉淀进规则文档，特例已记入 Task 信息；
  13. 可接受残留与所有破例记录原因。

反微调停机规则：死磕清单清空后，预计新一轮全图 similarity 提升 < 0.0005 时不得开启。
